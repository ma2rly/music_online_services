# Структура хранения музыкального онлайн-сервиса

## Общая модель

Каталог содержит 12 коллекций, каждая коллекция — список объектов с целочисленным уникальным `id` внутри своего раздела.

| Коллекция | Поля | Назначение |
| --- | --- | --- |
| `artists` | `id`, `name` | исполнители |
| `tracks` | `id`, `title`, `artist_id`, `duration_seconds`, `genre`, `album_id` | треки и их исполнители |
| `listeners` | `id`, `username` | пользователи |
| `playlists` | `id`, `name`, `owner_id`, `track_ids` | плейлисты и ID треков |
| `albums` | `id`, `title`, `artist_id`, `label_id` | альбомы, принадлежащие исполнителям |
| `genres` | `id`, `name` | справочник музыкальных жанров |
| `labels` | `id`, `name` | звукозаписывающие компании |
| `plans` | `id`, `name`, `monthly_fee` | тарифные планы, стоимость в условных целых единицах |
| `subscriptions` | `id`, `listener_id`, `plan_id`, `active` | подписки пользователей |
| `favorites` | `id`, `listener_id`, `track_id` | избранные треки пользователей |
| `reviews` | `id`, `listener_id`, `track_id`, `rating`, `text` | оценки треков от 1 до 5 |
| `history` | `id`, `listener_id`, `track_id`, `listened_seconds` | записи о прослушиваниях |

`album_id` и `label_id` могут быть `null` в JSON, тогда в XML атрибут не указывается. Значения `active` хранятся в JSON как `true` или `false`, в XML — как строковые атрибуты `"true"` / `"false"`.

Значения `artist_id`, `owner_id`, `track_ids`, `listener_id`, `plan_id`, `album_id`, `label_id` ссылаются на идентификаторы соответствующих записей. При чтении файла программа проверяет существование всех ссылок. При попытке удалить используемый объект программа выдаёт `ValidationError`.

## JSON

JSON-файл имеет корневой объект с полями-коллекциями, например:

```json
{
  "artists": [{"id": 1, "name": "Кино"}],
  "tracks": [{"id": 1, "title": "Группа крови", "artist_id": 1, "duration_seconds": 287, "genre": "Рок", "album_id": null}],
  "listeners": [{"id": 1, "username": "student"}],
  "playlists": [{"id": 1, "name": "Любимое", "owner_id": 1, "track_ids": [1]}],
  "albums": [],
  "genres": [],
  "labels": [],
  "plans": [],
  "subscriptions": [],
  "favorites": [],
  "reviews": [],
  "history": []
}
```

Сериализация: `json.dump()`. Десериализация: `json.load()`. Дополнительные коллекции могут отсутствовать в старом JSON-файле и тогда восстанавливаются пустыми.

## XML

Эквивалентные данные можно представить в XML:

```xml
<?xml version="1.0" encoding="utf-8"?>
<music_service version="2">
  <artists><artist id="1"><name>Кино</name></artist></artists>
  <tracks>
    <track id="1" artist_id="1" duration_seconds="287">
      <title>Группа крови</title><genre>Рок</genre>
    </track>
  </tracks>
  <listeners><listener id="1"><username>student</username></listener></listeners>
  <playlists>
    <playlist id="1" owner_id="1">
      <name>Любимое</name>
      <track_ids><track id="1" /></track_ids>
    </playlist>
  </playlists>
  <albums/><genres/><labels/><plans/><subscriptions/>
  <favorites/><reviews/><history/>
</music_service>
```

Сериализация: `xml.etree.ElementTree.ElementTree.write()`. Десериализация: `xml.etree.ElementTree.parse()`. XML версии `2` требует все 12 разделов; поддерживается чтение старого XML версии `1` с четырьмя основными разделами.

Полные примеры файлов: `catalog.json` и `catalog.xml` рядом с этим документом.
